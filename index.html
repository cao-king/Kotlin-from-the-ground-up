逻辑控制语句

程序怎么"做判断"和"重复做"？靠 if、when、for、while。

if 是表达式，能当值用

fun main() {
    val a = 10
    val b = 20
    // Java 里要写 int max; if(...) max=a; else max=b
    // Kotlin 直接把 if 当值赋给变量
    val max = if (a > b) a else b
    println("较大的是 $max")
}

when：升级版 switch

when 相当于 Java 的 switch，但更强大：可以判断区间、类型、甚至任意条件。

fun describe(score: Int): String {
    return when {
        score >= 90 -> "优秀"        // 每个分支用 -> 箭头，不用 break
        score >= 60 -> "及格"
        else        -> "不及格"
    }
}
fun main() {
    println(describe(85))   // 及格
}

循环：for 和 while

fun main() {
    // for 配合区间（后面区间章节会细讲）
    for (i in 1..3) print("$i ")     // 1 2 3

    // while：条件满足就一直转
    var x = 3
    while (x > 0) { print("$x "); x-- }   // 3 2 1
}

标签 break：跳出多重循环

Java 里想跳出外层循环要写标志位。Kotlin 给循环起个名字，break@名字 直接跳出去。

fun main() {
    outer@ for (i in 1..3) {        // 给外层循环起名 outer
        for (j in 1..3) {
            if (i + j > 3) break@outer   // 直接跳出外层，不只是内层
            print("($i,$j) ")
        }
    }
}

空安全与类型转换

这是 Kotlin 最革命性的特性。Java 里臭名昭著的 NullPointerException（空指针崩溃），在 Kotlin 里编译器就帮你挡住了。

可空类型与非空类型

Kotlin 默认变量不能是 null。想装 null，类型后面必须加一个 ?。

fun main() {
    var a: String = "abc"
    // a = null       // 报错！String 类型不接受 null

    var b: String? = "abc"   // String? 才是"可空字符串"
    b = null                 // 允许
}

三个空安全运算符（必背）

写法名字意思
?.安全调用对象非 null 才调用，否则整个表达式返回 null
?:Elvis 运算符"左边是 null 就用右边默认值"
!!非空断言"我保证它不是 null"，是 null 就真的崩给你看
fun main() {
    var name: String? = null

    // ?.：name 是 null 时不会崩溃，整句直接返回 null
    println(name?.length)        // null

    // ?:：左边是 null，就用右边这个默认值
    val len = name?.length ?: 0
    println("长度是 $len")       // 0

    // !!：强行断言非空（慎用）
    // println(name!!.length)    // 抛 NPE，和 Java 一样崩
}

类型转换：as? 安全转换

fun main() {
    val any: Any = "hello"
    // as?：转不成功返回 null，不崩
    val s: String? = any as? String
    println(s)   // hello
}
这一组语法学会，你写 Kotlin 基本不会再遇到空指针崩溃——这就是 Google 选它当 Android 官方语言的核心理由之一。

比较、区间与位运算符

这一节解决新手三个最懵的问题：Kotlin 里两个对象"相等"到底怎么判断？怎么优雅地写"从 1 数到 100"？为什么 Kotlin 不像 Java 那样写 &、|、<<？

1. 相等判断：== 与 === 的区别

先讲原理：Java 里 == 比的是"内存地址"（两个变量是不是堆里同一个对象），而 .equals() 比的是"内容"。这导致 Java 新手经常写出 if (str == "abc") 这种 bug。Kotlin 反过来设计：

  • ==：自动帮你调 equals()，比内容，还自动处理 null（左边是 null 也不会崩）。
  • ===：才是比内存地址，判断是不是同一个对象实例。
// data class 会自动帮你生成 equals() 和 hashCode()
// 规则：所有属性都一样，就认为两个对象"相等"
data class Person(val name: String)

fun main() {
    // new 出两个不同的对象，放在内存两个不同位置
    val a = Person("Tom")
    val b = Person("Tom")

    // == 比内容：名字都是 Tom，所以 true
    // 编译器实际展开成：a?.equals(b) ?: (b === null)，所以左边 null 也安全
    println(a == b)      // 输出 true

    // === 比地址：虽然内容一样，但它俩是两个 new 出来的对象
    println(a === b)     // 输出 false

    // 字符串是例外：JVM 有字符串常量池，"abc" 字面量会复用
    val c: String? = "abc"
    val d = "abc"
    println(c == d)      // true（内容相同）
    // println(c === d)  // 这里恰好也是 true，因为常量池复用，别记成规律
}
记忆口诀：日常判断"内容是否相同"一律用 ==；只有在你真的要判断"是不是同一个对象"时才用 ===。普通类（非 data class）若不重写 equals()，== 才退化成比地址。

2. 区间表达式：别再写 for (int i=0; i<n; i++)

先讲原理：Kotlin 把"一段连续的数字/字符"抽象成一个 Range 对象。你写 1..5，编译器就生成一个闭区间对象，它能被 for 循环遍历、能判断某个数在不在里面。

写法含义实际遍历结果
1..5闭区间，两头都包含1,2,3,4,5
1 until 5左闭右开，不包含 51,2,3,4
5 downTo 1从大往小倒数5,4,3,2,1
step 2每隔几个取一个1,3,5,7,9
'a'..'z'字符也能成区间a,b,c,…,z
fun main() {
    // 1..3：从 1 数到 3，包含 3
    for (i in 1..3) print("$i ")        // 打印：1 2 3

    // 6 downTo 0 step 2：从 6 倒数到 0，每次减 2
    for (i in 6 downTo 0 step 2) print("$i ")  // 打印：6 4 2 0

    // 实际开发最常用：判断成绩落在哪个分数段
    val score = 85
    when (score) {
        in 90..100  -> println("优")     // 90 到 100 都算优
        in 60 until 90 -> println("及格") // 60 到 89 算及格
        else         -> println("不及格")
    }

    // !in 表示"不在区间内"
    val age = 150
    if (age !in 0..120) println("年龄不合法")
}
为什么要有 until？数组/列表下标是从 0 开始、长度是 n，合法下标是 0 到 n-1，正好是 0 until list.size。写 0..list.size-1 容易漏写 -1。

补充：is 类型判断与智能转换

is 判断对象是不是某个类型，相当于 Java 的 instanceof。更爽的是：判断完以后，编译器自动把它当那个类型用，不用强转。

fun describe(o: Any) {
    if (o is String) {
        // 编译器知道 o 是 String，直接当 String 用，不用强转
        println("长度是 ${o.length}")
    } else if (o is Int) {
        println("整数是 ${o + 1}")
    }
}

3. 位运算符：为什么 Kotlin 不用 & | <<

先讲原理：Java 里 <<、& 是运算符，但它们只能用在数字上。Kotlin 设计时想让语法更统一，干脆把这些操作做成了中缀函数——看起来像函数调用，读起来更像自然语言。注意它们只能用在 Int / Long 上。

Kotlin 写法等价 Java作用（看二进制位）
shl(n)<<所有二进制位左移 n 位（相当于 ×2ⁿ）
shr(n)>>右移，保留正负号
ushr(n)>>>无符号右移（高位补 0）
and(b)&两位都为 1 才得 1
or(b)|任意一位为 1 就得 1
xor(b)^两位不同才得 1
inv()~0 变 1、1 变 0
fun main() {
    // 0b 前缀表示二进制字面量，0b1010 = 十进制 10
    val mask = 0b1010

    // shl 1：左移一位，1010 -> 10100 = 20
    println(mask shl 1)        // 20

    // and：1010 & 1100 = 1000 = 8
    println(mask and 0b1100)   // 8

    // inv：每一位取反
    println(mask.inv())        // -11（补码表示）
}

// 真实用途：用一个 Int 的不同二进制位存多个开关状态
// 例如 FLAG_READ=1(0001), FLAG_WRITE=2(0010), FLAG_DELETE=4(0100)
fun checkPermission(mode: Int): Boolean {
    // mode 与 FLAG_READ 按位与，结果非 0 表示"读"这个开关打开了
    return mode and 1 != 0
}

继承

子类"白嫖"父类的属性和方法，再加点自己的东西。Kotlin 默认类是不能被继承的，必须加 open 关键字——这是和 Java 最大的区别。

open class Animal(val name: String) {   // open：允许被继承
    open fun speak() = "$name 叫了一声"   // open：允许子类重写
}
class Dog(name: String) : Animal(name) {  // 继承用 :
    override fun speak() = "$name 汪汪汪"   // override 必须显式写
}
fun main() {
    val d = Dog("旺财")
    println(d.speak())   // 旺财 汪汪汪
}
Java 里类默认能被随便继承，导致很多坑。Kotlin 反其道而行：默认锁死，想被继承必须写 open。

类型别名 typealias

一句话：给一个已有类型起个更好读的外号。它不创造新类型，编译器看到外号就替换成原名。

为什么需要它

项目里函数类型写长了，比如 (String, Int) -> Unit，到处粘贴很难读；泛型嵌套 Map<String, List<Pair<Int, String>>> 更是一眼看不懂。typealias 就是给它起个短名字。

// 给 Long 起个有业务含义的名字：用户ID

// 给复杂泛型起名字：键是字符串、值是"整数-字符串"列表的映射

// 用的时候，写外号和写原类型完全等价
fun loadUser(id: UserId, listener: Listener) {

}

// Android 里常见：把点击回调起别名

解构声明 Destructuring Declarations

一句话：把一个对象"拆开"，一次声明出多个变量。

原理：componentN() 运算符

写 val (name, age) = user 时，编译器其实在调用 user.component1() 和 user.component2()。data class 会自动按属性顺序生成这两个函数。

// data class 自动生成 component1()、component2()...
data class User(val name: String, val age: Int)

fun main() {
    val u = User("Tom", 28)

    // 下面这一行 ≈ val name = u.component1(); val age = u.component2()
    val (name, age) = u
    println("$name 今年 $age 岁")   // Tom 今年 28 岁

    // 最常见场景：函数要返回两个值，用 Pair
    fun minMax(list: List<Int>): Pair<Int, Int> {
        return Pair(list.min(), list.max())
    }
    // 直接拆开接两个变量，不用写 .first .second
    val (min, max) = minMax(listOf(3, 1, 9, 5))
    println("最小=$min 最大=$max")

    // 遍历 Map 时也能拆
    val map = mapOf("姓名" to "Tom", "年龄" to 28)
    for ((key, value) in map) {
        println("$key = $value")
    }
}

普通类想支持解构，自己写 operator 函数

class Point(val x: Int, val y: Int) {
    // operator 关键字告诉编译器：这是 componentN 运算符
    operator fun component1() = x   // 第一个变量拿 x
    operator fun component2() = y   // 第二个变量拿 y
}
fun main() {
    val (x, y) = Point(3, 4)   // 不用 data class 也能拆
}
下划线忽略：不想要某个值就写 _，例如 val (_, age) = u 只取年龄。Lambda 里也能用：map.forEach { (k, v) -> println(k) }。

对象声明与伴生对象

Kotlin 没有 Java 的 static 关键字。它用两套语法替代：object 表示"整个类只有一个实例"，companion object 表示"挂在类上的静态成员"。

1. object：直接写出一个单例

// object 声明 = 类声明 + 立刻 new 一个唯一实例，一步到位
object Settings {
    var theme: String = "dark"      // 就像全局变量
    fun reset() { theme = "dark" }  // 就像静态方法
}

fun main() {
    // 直接用类名当对象用，整个程序只有这一份
    Settings.theme = "light"

}

2. companion object：类的"静态区"

class User private constructor(val name: String) {
    // 写在 companion object 里的东西，调用方式和 Java 静态成员一样
    companion object {
        const val TAG = "User"              // 静态常量
        fun fromJson(json: String): User {  // 静态工厂方法
            // 因为在 companion 里，所以能调用 private 构造函数
            return User(json)
        }
    }
}

fun main() {
    // 像调静态方法一样调
    val u = User.fromJson("Tom")
    println(User.TAG)
}
为什么私有构造 + companion 工厂很常见？它强迫调用方只能通过 User.fromJson() 创建对象，而不能随便 new User()，这样创建逻辑就集中管控了。

3. 对象表达式：临时匿名对象

    override fun onClick(v: View?) {
        println("点了一下")

})

// 因为 View.OnClickListener 只有一个方法（SAM 接口），Kotlin 可以简化成 lambda
view.setOnClickListener { println("点了一下") }

内联函数 inline

一句话：告诉编译器"别真的调用这个函数，把函数体直接搬进调用处"，顺便把 lambda 对象也省掉。

先搞清楚：为什么高阶函数会变慢？

当你把 lambda 传给一个函数时，JVM 底层通常会为这个 lambda 创建一个 FunctionN 接口的匿名对象。每次调用都 new 一个对象，高频执行时就会产生大量临时对象，拖慢速度、增加 GC 压力。

inline 的原理：编译时，编译器把函数体和你传进去的 lambda 代码直接复制粘贴到调用的地方，根本不发生真实的函数调用，也不创建 lambda 对象。

// 这个函数接收一个 lambda block，返回它执行的结果
inline fun <T>.measure(block: () -> T): T {
    val start = System.nanoTime()   // 记录开始时间
    val r = block()                 // 执行传进来的代码
    println("耗时 ${System.nanoTime() - start} ns")
    return r
}

fun main() {
    // 加了 inline 后，下面这行不会真的调用 measure、也不 new lambda 对象
    // 而是把 measure 函数体和 Thread.sleep(10) 一起塞进这里
    measure { Thread.sleep(10) }
}

noinline 与 crossinline

inline fun foo(
    crossinline onOk: () -> Unit,   // 这个 lambda 会在别的地方被调用
    noinline onError: () -> Unit    // 明确告诉编译器：这个别内联
) { /* ... */ }
  • noinline：内联函数里，如果你想把某个 lambda 存起来（比如塞进集合以后再用），就不能内联它，必须加 noinline。
  • crossinline：你的 lambda 会在另一个执行上下文（比如另一个线程、另一个对象）里被调用，这时 lambda 里就不能直接用裸 return 跳出外层函数了。

reified：在运行时还能拿到泛型类型

原理：Java/Kotlin 的泛型有"类型擦除"——运行时 List<String> 和 List<Int> 都只是 List。但因为 inline 函数被拷贝到了调用处，编译器知道那里传的是 String，用 reified 就能把这个信息带到运行时。

// 不写 reified，运行时根本不知道 T 是什么，x is T 编译报错
// 写了 reified + inline，编译器在每个调用点把真实类型填进去
inline fun <reified T>.isA(x: Any): Boolean = x is T

fun main() {
    isA<String>("hello")   // true
    isA<Int>("hello")       // false
}
标准库的 lock {}、with {}、apply {}、also {} 全都是 inline 函数——它们既省对象，又让代码写起来特别顺。

泛型与型变

泛型 = "类型的模板"。写一份代码，能套 Int、String、User 用。难的是：List<Int> 能不能当 List<Number> 用？这就是型变要解决的问题。

1. 为什么需要泛型

// 不写泛型：只能装 Any，取出来要强转，容易 ClassCastException
// class Box { var item: Any? = null }

// 写了泛型：编译期就知道里面装的是什么类型
class Box<T>(var item: T)   // T 是"类型参数"，用的时候再指定

fun main() {
    val intBox = Box<Int>(1)        // T = Int
    val strBox = Box<String>("hi") // T = String
    intBox.item + 10                // 编译器知道是 Int，能直接加
}

2. out / in：协变与逆变（最容易懵的部分）

核心问题：Int 是 Number 的子类，那 Box<Int> 是不是 Box<Number> 的子类？

标记名字这个类对 T 做了什么能不能当父类用例子
out T协变只产出 T（返回 T），从不接收 T可以，Box<Int> 就是 Box<Number>只读 List
in T逆变只消费 T（传入 T），从不返回 T反过来，Box<Number> 可以当 Box<Int>比较器
不加不变既能读也能写互相不能赋值MutableList
// 只往外拿 T：生产者
interface Source<out T> { fun next(): T }

// 只往里塞 T：消费者
interface Sink<in T> { fun put(t: T) }

fun copy(from: Source<out Number>, to: Sink<in Number>) {
    // from 是协变的，传 Source<Int> 也合法（Int 是 Number 子类）
    // to 是逆变的，传 Sink<Any> 也合法（Any 是 Number 父类）
}
记忆口诀：PECS —— Producer 使用 out，Consumer 使用 in。你只读不写就 out，只写不读就 in。

扩展函数与扩展属性

一句话：不改 String 类源码、不继承它，也能"给它加个方法"。调用起来就像它本来就有这个方法一样。

// 语法：fun 接收者类型.函数名(参数) { ... }
// 这里的 this 就代表调用这个方法的那个字符串本身
fun String.isPhone(): Boolean {
    // 校验是否为 11 位手机号
    return this.matches(Regex("^1\\d{10}$"))
}

// 扩展属性：给 String 加一个"最后一个字符"
val String.lastChar: Char
    get() = this[this.length - 1]   // this 是这个字符串

fun main() {
    // 调用起来就像 String 自带的方法
    println("13800001111".isPhone())  // true
    println("abc".lastChar)            // c
}

原理与最大的坑：扩展是"静态解析"的

扩展并没有真的修改类。编译后它其实是一个静态方法，接收者作为第一个参数传进去。因此，编译器看的是变量的声明类型，而不是运行时真正的对象类型——这和成员方法的多态不一样。

open class Shape

// 给 Shape 加扩展
fun Shape.desc() = "shape"
// 给 Circle 加扩展
fun Circle.desc() = "circle"

fun main() {
    val s: Shape = Circle()   // 声明类型是 Shape，实际对象是 Circle
    println(s.desc())         // 打印 "shape"！因为看的是 Shape
}

  • 可以给可空类型加扩展：fun String?.isEmptyOrNull() = this == null || this.isEmpty()，连 null 调用都不崩。
  • Android 开发最爱用它：把 Toast.makeText(ctx, "...", LENGTH).show() 封装成 ctx.toast("...")，告别各种 Utils.xxx(a, b)。

异常处理

一句话：程序出错时怎么不崩溃地"接住"错误。Kotlin 比 Java 简单——没有受检异常，不用在函数签名上写 throws。

try-catch-finally 怎么写

fun readFile(path: String): String {
    return try {
        // 可能出错的代码放这里：读文件可能抛 IOException
        java.io.File(path).readText()
    } catch (e: java.io.IOException) {
        // 出错了就进来这里：e 是异常对象，e.message 是错误信息
        println("读取失败: ${e.message}")
        "默认内容"          // 这个值作为函数返回值
    } finally {
        // 不管成功失败，最后都会执行（常用来关流、释放资源）
        println("总是执行")
    }
}

Kotlin 里 try 是"表达式"，能当值用

fun main() {
    // try 块最后一个表达式的值，就是整个 try 的值
    val number = try {

        0                   // 失败就用 0
    }

委托与委托属性

"委托"就是：自己不想干的活，甩给别人干。Kotlin 用一个 by 关键字就实现了。

1. 类委托：接口方法转发给别人

interface IList { fun size(): Int }

// by inner：IList 里要求实现的所有方法，自动转发给 inner 对象
// 不用自己一个个手写 override
class MyList(val inner: List<String>) : IList by inner

fun main() {

}

2. 最常用的：标准委托属性

属性的 getter/setter 也可以"委托"给一个工具对象。下面这三个是日常开发最高频的：

class User {
    // lazy：第一次访问 avatar 时才执行花括号里的代码，之后缓存结果
    // 适合加载图片、读大文件这种"用得到才加载"的场景
    val avatar: String by lazy {
        println("真正加载网络图片...")
        "https://.../avatar.png"
    }

    // observable：属性每次被赋值，就回调一次 old -> new
    var name: String by Delegates.observable("<init>") { property, old, new ->
        println("$old 变成了 $new")
    }

    // vetoable：赋值前先过一道检查，返回 false 就拒绝这次更新
    var age: Int by Delegates.vetoable(0) { property, old, new ->
        new > 0    // 只有新值大于 0 才允许改
    }
}

// 还有一个常用：把对象字段直接存在一个 Map 里（从 JSON 解析出来时很爽）
class Config(map: Map<String, Any?>) {
    val host: String by map   // 自动从 map["host"] 取值
    val port: Int by map
}
fun main() {
    val u = User()
    u.name = "Tom"     // 打印 "<init> 变成了 Tom"
    u.age = -5         // 被拒绝，age 还是 0
}

val x by 某对象 等价于：读 x 时调用 某对象.getValue()，写 x 时调用 某对象.setValue()。所以你可以自己写委托：

class LoggingProp<T>(var v: T) {

        println("读取属性 ${p.name} = $v")
        return v
    }
    operator fun setValue(thisRef: Any?, p: KProperty<*>, nv: T) {
        println("写属性 ${p.name}: $v -> $nv")
        v = nv
    }
}

    val ageProp = Person::age

    println(p::class.simpleName)          // "Person"
}

协程深入（Coroutine /ˌkɒruːˈtiːn/）

一句话：用"从上到下顺序写"的代码，去做异步任务（网络请求、延时），再也不写层层嵌套的回调。这是 Kotlin 最强大、面试最爱问的特性。

1. 为什么需要协程：先看回调地狱

没有协程时，Android 网络请求要靠回调嵌套：

// 丑到爆炸：三个请求层层嵌套，叫"回调地狱"
fetchUser { user ->
    fetchOrder(user.id) { order ->
        fetchGoods(order.id) { goods ->
            render(goods)
        }
    }
}

协程让你写成这样，效果一样，但代码是直线的：

suspend fun loadPage() {
    val user = fetchUser()          // 等 user 回来，再走下一行
    val order = fetchOrder(user.id)
    val goods = fetchGoods(order.id)
    render(goods)
}

2. 核心原理：挂起 ≠ 阻塞

这是理解协程的钥匙：

Thread.sleep(1000)delay(1000)
线程状态真的被占住，休眠 1 秒线程被释放，去干别的活
系统代价重（一个线程占 1MB 栈）极轻（几KB）
同时能跑多少几千个就爆了几十万个都没问题

底层原理：你写的 suspend fun，编译器会自动把它改造成一个状态机——遇到 delay() 这种挂起点，函数就"打包存档"返回，线程还给别人用；时间到了，再从存档点继续跑。这个过程对你透明，你写起来像同步代码。

3. 三个核心角色：Scope / Dispatcher / Job

  • CoroutineScope（作用域）：管理一批协程的"大管家"，它死了，手下所有协程一起死。Android 里用 viewModelScope、lifecycleScope。
  • Dispatcher（调度器）：指定协程跑在哪个线程。Dispatchers.Main=主线程（改 UI）、Dispatchers.IO=IO 线程池（网络/磁盘）、Dispatchers.Default=CPU 密集计算。
  • Job：协程的句柄，可以 cancel() 取消它。

4. 启动器全家桶

fun main() = runBlocking {       // ① runBlocking：阻塞当前线程，桥接用
    launch {                       // ② launch：启动一个"发了就不管"的协程
        delay(1000)
        println("launch 完成")
    }
    val deferred = async {         // ③ async：启动一个要返回结果的协程
        delay(500)
        "我是结果"
    }
    val result = deferred.await()  // ④ await：挂起等结果，不阻塞线程
    println(result)
}
API用途
runBlockingmain 函数 / 单元测试里用，别在 Android 正式代码里用
scope.launch { }启动不需要返回值的后台任务（刷新列表、埋点）
scope.async { }启动需要返回结果的任务，.await() 取值
coroutineScope { }创建子作用域，等里面所有子协程都完成才结束
suspend fun标记这是个可挂起函数，只能在协程里调用

5. 并发：两个请求同时发

suspend fun fetchUser(): User { /* 网络请求 */ }
suspend fun fetchOrder(): Order { /* 网络请求 */ }

suspend fun loadPage() = coroutineScope {
    // async 立刻同时发两个请求，不是串行！
    val userDeferred = async(Dispatchers.IO) { fetchUser() }
    val orderDeferred = async(Dispatchers.IO) { fetchOrder() }

    // await：挂起等结果。两个请求并行跑，总耗时 = 最慢的那个
    val user = userDeferred.await()
    val order = orderDeferred.await()
    render(user, order)
}

6. 结构化并发：父子作用域

这是协程最优雅的设计：父协程会等所有子协程都结束才结束；子协程抛异常，父协程也会取消。你不用手动管线程的生命周期。

suspend fun demo() = coroutineScope {
    launch { delay(1000); println("A") }
    launch { delay(2000); println("B") }
    // 这一行等 A 和 B 都打完才继续
    println("全部完成")
}

7. 取消与异常

val job = scope.launch {
    try {
        repeat(1000) { i ->
            delay(500)
            println(i)
        }
    } finally {
        // 协程被取消时一定会走这里，清理资源
        println("被取消了，关闭连接")
    }
}
// 外面想停就停
scope.launch { delay(2000); job.cancel() }
新手坑：协程取消是合作式的——它只是发个"该取消了"的信号，你的代码里必须有 delay() 这种挂起点才能响应取消。纯 CPU 死循环不挂起，cancel 了也停不下来。

竖直显示的 TextView

自定义 View，把每个字符竖直依次绘制。核心思路：重写 onDraw，逐字往下画。

class VerticalTextView(context: Context, attrs: AttributeSet?) :
    View(context, attrs) {

    var text: String = ""
        set(value) { field = value; requestLayout(); invalidate() }

    private val paint = Paint(Paint.ANTI_ALIAS_FLAG).apply {
        textSize = 40f
        color = 0xFF222222.toInt()
    }

    override fun onMeasure(widthMeasureSpec, heightMeasureSpec) {
        // 宽度 = 一个字宽 + padding；高度 = 字数 * 行高
        val w = (paint.measureText("我") + paddingLeft + paddingRight).toInt()
        val h = (text.length * paint.fontMetrics.let { it.descent - it.ascent }
                + paddingTop + paddingBottom).toInt()
        setMeasuredDimension(w, h)
    }

    override fun onDraw(canvas: Canvas) {
        super.onDraw(canvas)
        val x = paddingLeft.toFloat()
        var y = paddingTop.toFloat() - paint.fontMetrics.ascent
        for (ch in text) {
            canvas.drawText(ch.toString(), x, y, paint)
            y += paint.fontMetrics.let { it.descent - it.ascent }
        }
    }
}

第一个 Composable 函数

用 @Composable 注解标记的函数，就是一个"可组合的 UI 块"。它能接收数据，输出一段界面。

// @Composable 告诉编译器：这是一个 UI 函数
@Composable
fun Greeting(name: String) {
    // Text 本身也是一个 @Composable 函数
    Text(
        text = "你好, $name",
        style = TextStyle(fontSize = 24.sp, color = Color(0xFF7F52FF))
    )
}

// 在 Activity 里挂上去：
class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContent {              // 把 Composable 树挂到屏幕上
            Greeting("Tom")
        }
    }
}
记住一个规矩：@Composable 函数不返回值（Unit），它的工作就是描述界面。

状态：remember 与 mutableStateOf

UI 上显示的数据叫"状态"。状态一变，Compose 自动重新调用这个函数、刷新界面。

@Composable
fun Counter() {
    // mutableStateOf：包一个可观察的数据
    // remember：让这个数据在重组时不被重置
    var count by remember { mutableStateOf(0) }

    Column {
        Text("点了 $count 次")
        Button(onClick = { count++ }) {   // 点一下，count 变了
            Text("点我 +1")                  // Text 自动刷新
        }
    }
}
  • mutableStateOf(0)：把 0 变成"可观察"的数据，谁读它就订阅它。
  • remember { }：Compose 可能因各种原因重新执行这个函数，remember 让值记住上次的，不重置。
  • by 属性委托：让你直接写 count 而不是 count.value。

容器方向类比

@Composable
fun MyLayout() {
    Column(
        modifier = Modifier.padding(16.dp),        // 外边距
        verticalArrangement = Arrangement.Center    // 垂直居中
    ) {
        Text("第一行")
        Row {
            Text("左")
            Spacer(Modifier.width(8.dp))
            Text("右")
        }
    }
}
Modifier 是 Compose 里最常用的对象：padding、大小、背景、点击、圆角全靠它链式加。

列表：LazyColumn（代替 RecyclerView）

别再写 RecyclerView.Adapter 了。Compose 的 LazyColumn 一行搞定，自动回收复用。

@Composable
fun UserList(users: List<String>) {
    LazyColumn {
        items(users) { name ->       // 每个列表项
            Text(text = name, modifier = Modifier.padding(8.dp))
        }
    }
}
